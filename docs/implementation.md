# Implementation and validation record

Baseline: README only, no existing code. Track work through issues #1–#9. Current branch: implementation/virtualization-backend.

## Initial slice
A Vinext route handler validates a strict minimal ComputerSpec and uses a namespace-scoped Kubernetes service account to submit actual KubeVirt VM and lifecycle operations. The test-only bearer identity is configured in a Kubernetes Secret. Drizzle/PostgreSQL stores operation IDs and idempotency keys; ambiguous operations remain unknown rather than being blindly retried. The CI uses a disposable hosted runner and fails if /dev/kvm is absent; software emulation is not enabled. The current boot disk is deliberately ephemeral, with a mutable CirrOS demo image tag; it is NOT the persistent disk or image acquisition implementation. There is no network attached to this initial VM. No general dashboard or public ingress.

## Test and run
Use the GitHub Actions workflow; do not run the provisioning script on an existing cluster. Local unit tests: npm install, npm run typecheck, npm run lint, npm test, npm run build. The full job installs operators, deploys a database and application, port-forwards only the application API and runs scripts/e2e-smoke.py. The smoke tests inspect KubeVirt-reported VMI phase; this is not proof of guest login, desktop, or actual input. No image or capability is certified until suitable tests pass.
